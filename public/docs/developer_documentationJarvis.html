Jarvis – AI Knowledge Base

Jarvis is a multi-tenant RAG platform that turns company documents into a cited, grounded AI assistant. Workspaces upload PDFs, DOCX files, and SOPs. A FastAPI backend extracts, chunks, and embeds the text into a pgvector database. Employees then ask business questions and receive inline-cited answers that trace every claim back to its source document.

Product Purpose

A company knowledge layer where every answer is traceable to a real document chunk. Not a general chatbot — Jarvis only answers from what your company has uploaded.

Operational Flow

Document upload → text extraction → chunking → Gemini embedding → pgvector storage. Question → semantic search → context assembly → Gemini chat → cited answer.

System Architecture

The system has two distinct runtime layers. The Next.js frontend handles auth, workspace management, and the UI. The FastAPI backend owns all document processing, vector embedding, similarity search, and AI answer generation. The two layers communicate over authenticated REST.

Public Routes

Protected Workspace

Dashboard, Documents, Assistant, Knowledge Capture, Search, Context preview, and Settings — all scoped to the authenticated user's company.

Multi-tenant Isolation

Every document, chunk, embedding, and knowledge entry carries a company_id. RLS policies on Supabase enforce row-level isolation — one workspace never touches another's data.

Database Schema

Supabase Postgres stores all workspace data. RLS is enabled on every table. The pgvector extension powers cosine-similarity semantic search over the document_embeddings table through the search_document_chunks RPC.

Table Description Key Fields
profiles One profile per Supabase Auth user. id, email, full_name
companies A workspace / tenant. Created once per organization at sign-up. id, name, slug, created_by
memberships Links users to companies. Controls role-based access. user_id, company_id, role (owner / admin / member), status
documents Uploaded files with lifecycle status tracking. company_id, title, file_type (pdf / docx / txt), storage_path, status (uploaded / processing / processed / failed), extracted_text
document_chunks Text chunks produced by the chunking pipeline. Immutable after insert. document_id, chunk_index, content, character_count, estimated_token_count, metadata
document_embeddings 768-dimensional Gemini vectors stored in pgvector. Immutable after insert. chunk_id, company_id, embedding, embedding_model, embedding_dimension
knowledge_entries Structured knowledge captured through guided templates before publishing into the RAG pipeline. company_id, title, category, status (draft / generated / published), template_id, answers, published_document_id
activity_logs Append-only audit trail of workspace actions. company_id, user_id, action, metadata

Semantic Search RPC

-- Supabase database function (pgvector)
search_document_chunks(
  p_company_id    uuid,
  p_query_embedding vector(768),
  p_match_count   int  -- default 5
)
RETURNS TABLE (
  chunk_id         uuid,
  document_id      uuid,
  document_title   text,
  chunk_index      int,
  similarity_score float,
  content          text,
  metadata         jsonb
)

The RPC uses cosine similarity (<=> operator) scoped by company_id so each workspace only searches its own embeddings. Called by the retrieval service on every assistant question.

RAG Pipeline

The Retrieval-Augmented Generation pipeline has two distinct phases: document ingestion (offline) and query answering (online). Both are stateless operations — any state lives in Supabase.

Ingestion Phase

sequenceDiagram participant U as User participant API as FastAPI participant DP as DocumentProcessor participant DC as DocumentChunker participant ES as EmbeddingService participant G as Gemini Embedding participant DB as Supabase U->>API: Upload file (PDF / DOCX / TXT) API->>DB: Store file in Storage bucket API->>DB: Insert document row (status=uploaded) U->>API: POST /documents/{id}/process API->>DP: extract_text(file_type, content) DP->>DP: Normalize whitespace, strip soft hyphens DP->>API: ExtractionResult(extracted_text) API->>DC: RecursiveChunkStrategy.chunk(text) DC->>API: list[KnowledgeChunk] (1000 chars, 200 overlap) API->>DB: Insert document_chunks rows API->>ES: generate_for_document(document_id) ES->>G: embedContent for each chunk G->>ES: 768-dim vector (L2-normalized) ES->>DB: Insert document_embeddings rows API->>DB: Update document status=processed

Chunking Strategy

Chunk Size

1,000 characters per chunk. Long paragraphs are split at sentence boundaries (. ? ! ; ,) before falling back to word boundaries.

Overlap

200-character overlap between adjacent chunks to preserve cross-boundary context for retrieval.

Embedding

gemini-embedding-2 produces 768-dim vectors, L2-normalized before storage. Versioned via embedding_version.

Query Phase

sequenceDiagram participant U as User participant API as FastAPI /assistant participant RS as RetrievalService participant CB as ContextBuilderService participant AI as AIGenerationService participant G as Gemini Chat participant DB as Supabase pgvector U->>API: POST /assistant { question } API->>RS: search(query, limit=5) RS->>G: embed(question) → 768-dim vector RS->>DB: search_document_chunks(company_id, vector) DB->>RS: ranked chunks with similarity_score RS->>CB: build_context(chunks, max_context_chars) CB->>CB: dedupe chunks, fit to character budget CB->>CB: format numbered [Source N] blocks CB->>AI: ContextBuildResponse AI->>AI: calculate_confidence(best_score) AI->>G: generate(system_instructions, prompt) G->>AI: answer with inline [1] [2] citation markers AI->>AI: extract_citations(answer, chunks) AI->>U: AssistantResponse { answer, citations, sources, confidence }

API Reference

All routes are prefixed with /api/v1 and require a valid Supabase JWT unless noted.

Documents

GET /documents — list the company's uploaded documents.

POST /documents/{id}/process — trigger the full ingestion pipeline: extract → chunk → embed → store. Returns processing status.

Assistant (RAG)

POST /assistant — ask a business question. Returns answer, inline citations, sources list, confidence level, and whether context was truncated.

Search and Context

POST /search — run a raw semantic search against the company's document embeddings. Returns ranked KnowledgeSearchResult items with similarity scores.

POST /context — build a formatted context block from a query without calling the AI. Useful for debugging retrieval quality before the answer step.

Knowledge Capture

GET /capture/templates — list available capture templates (SOP, FAQ, Policy, Process, Checklist).

POST /capture/draft — save a manual draft from template answers.

POST /capture/generate — send template answers to Gemini and get an AI-drafted knowledge document back.

POST /capture/publish — push a finalized draft into the full document ingestion pipeline so it becomes searchable in the RAG assistant.

Auth and Health

POST /auth/* — workspace sign-up including create_initial_workspace Supabase RPC call.

GET /health — liveness probe. No auth required.

Service Layer

ServiceResponsibility
document_processor.py Extracts raw text from PDF (pypdf layout mode), DOCX (paragraph + table walk), and TXT. Normalizes whitespace, soft hyphens, and form feeds. Validates file magic bytes before attempting parse.
document_chunker.py RecursiveChunkStrategy: paragraph-aware chunking at 1,000 chars / 200 overlap. Finds semantic boundaries (sentence endings, commas, spaces) before hard splits.
embedding_service.py Generates Gemini embeddings for all chunks of a document. Deletes stale embeddings before re-embedding. Verifies company_id ownership per chunk.
embedding_provider.py GeminiEmbeddingProvider — calls embedContent REST API, validates vector dimension, and L2-normalizes the output before returning.
retrieval_service.py Embeds the user query, calls search_document_chunks Supabase RPC, maps results to KnowledgeSearchResult schema. Scoped to the user's active company membership.
context_builder_service.py Deduplicates retrieved chunks, fits them within a character budget, formats numbered [Source N] blocks, and aggregates source-level metadata. Signals if context was truncated.
ai_generation_service.py Calls Gemini chat with grounded system instructions and formatted context. Extracts [N] citation markers from the answer and maps each back to a chunk and document.
knowledge_capture_service.py Handles the full Knowledge Capture lifecycle: draft save, AI draft generation, and publish (which calls the document ingestion pipeline to make the entry searchable).
document_service.py SupabaseDocumentClient — all Supabase REST calls for documents, chunks, embeddings, memberships, and activity logs. Service-role and user-role clients used appropriately.
ai_provider.py GeminiChatProvider — calls the Gemini generateContent REST API with system instructions and prompt. Returns the text response.

Core Workflows

The two workflows that matter most: ingesting a document into the knowledge base, and answering a question with grounded citations.

Knowledge Capture Flow

Users without a document to upload can capture knowledge through a guided interview. The capture flow lets them fill in a structured template (SOP, FAQ, Policy, etc.), generate an AI-written draft, edit it, and then publish it — which pushes it through the same chunking and embedding pipeline as a regular document.

1

Template Selection

CAPTURE

User picks a template type: SOP, Department Process, FAQ, Policy, or Checklist. Each template provides structured guided questions (e.g. purpose, steps, owner, exceptions for an SOP).

2

AI Draft Generation

GEMINI

Answers are sent to POST /capture/generate. The backend builds a structured prompt from the template and answers, calls Gemini, and returns a formatted knowledge document draft. The draft is saved to knowledge_entries with status=generated.

3

Review and Edit

USER ACTION

Users can review and edit the draft in the UI. POST /capture/draft saves changes. The content field holds the current document body.

4

Publish into RAG Pipeline

PIPELINE

POST /capture/publish writes the content to Supabase Storage as a .txt file, inserts a documents row, runs the full ingestion pipeline (extract → chunk → embed), and updates the knowledge_entry to status=published with a reference to the generated document_id. The entry is now searchable by the RAG assistant.

5

Grounded Answer with Citations

ASSISTANT

A user question hits POST /assistant. The system embeds the query, retrieves the top-N chunks by cosine similarity, assembles a context block with numbered [Source N] labels, and sends it to Gemini with strict grounding instructions. The model writes inline citation markers ([1], [2]…) which are parsed back out and linked to specific chunks and documents. The response includes answer text, citations, source documents, and a confidence level.

Dual Supabase Clients

Most reads use the user's JWT (user-scoped client). Operations that need to bypass RLS — like writing embeddings or processing documents — use the service-role key. This prevents escalation while keeping the pipeline functional.

Gemini Models

gemini-embedding-2 produces 768-dim vectors for both document chunks and query embedding. gemini-2.5-flash handles both assistant answer generation and Knowledge Capture AI drafting. Both are configurable via environment variables.

Security Notes

Authentication

  • Supabase email/password auth. JWT verified on every FastAPI request through the get_current_user dependency.
  • Workspace creation uses a transactional Supabase RPC (create_initial_workspace) to atomically create the company and owner membership.
  • Middleware on the Next.js side redirects unauthenticated users to /auth/sign-in.

Data Isolation

  • RLS enabled on all tables. Users can only access rows where company_id matches their active membership.
  • Semantic search is always scoped by company_id — a workspace's embeddings are invisible to other tenants.
  • Chunk ownership is verified in the embedding service before generating vectors.

Prompt Injection Defense

  • System instructions explicitly tell Gemini to treat uploaded document text as untrusted source material, not executable instructions.
  • The context block labels content as "Retrieved source context" and instructs the model to ignore instructions embedded inside documents.
  • Answers use only the supplied context — the model is instructed to say "I don't know" rather than hallucinate.

File Validation

  • PDF extractor checks for %PDF magic bytes. DOCX extractor checks for PK ZIP header.
  • Encrypted PDFs are rejected with a clear error message.
  • Empty or unextractable documents fail at the processing stage with a descriptive error stored in extraction_error.

Roadmap and Boundaries

Currently Implemented

  • Multi-tenant workspaces with owner / admin / member roles.
  • PDF, DOCX, and TXT text extraction with normalization.
  • Recursive paragraph-aware chunking (1,000 chars / 200 overlap).
  • Gemini embedding-2 vector generation with L2 normalization.
  • pgvector cosine-similarity semantic search scoped by tenant.
  • Inline-cited RAG answers with confidence scoring (high / medium / low).
  • Knowledge Capture: guided templates → AI draft → publish into RAG.
  • Prompt injection defense through system instructions and content labeling.
  • Activity logging for all key workspace events.

Future Work

  • Background async processing queue (currently synchronous on request).
  • OCR support for image-only or scanned PDFs.
  • Re-embedding pipeline when the embedding model changes (versioned via embedding_version).
  • Document deletion cascading chunks and embeddings.
  • Member invitation flow (memberships can carry status=invited).
  • Answer streaming for the assistant endpoint.
  • Usage analytics and per-workspace document quotas.
